# Desktop browser bridge

Implementation: `packages/desktop/src-tauri/src/browser.rs`. Initial native support is macOS. Other platforms reject creation; render the web fallback instead. Use `invoke` from `@tauri-apps/api/core` in the trusted main RIFT webview only.

## IPC

Arguments use camelCase. Every `tabId` must be a canonical lowercase, hyphenated UUID generated by the frontend. Native view labels are private and must never be supplied by callers.

| Command | Arguments | Result |
| --- | --- | --- |
| `browser_tab_create` | `{ tabId, url }` | `BrowserSnapshot` |
| `browser_tab_navigate` | `{ tabId, url }` | `BrowserSnapshot` |
| `browser_tab_action` | `{ tabId, action: "back" \| "forward" \| "reload" \| "stop" }` | `BrowserSnapshot` |
| `browser_tab_snapshot` | `{ tabId }` | `BrowserSnapshot` |
| `browser_tab_layout` | `{ tabId, bounds: { x, y, width, height }, visible }` | `null` |
| `browser_tab_close` | `{ tabId }` | `null` |
| `browser_tabs_hide_all` | `{}` | `null` |

```ts
type BrowserSnapshot = {
  tabId: string;
  url: string;
  title: string;
  loading: boolean;
  canGoBack: boolean;
  canGoForward: boolean;
};
```

No events or page-to-app JavaScript callbacks are registered. Poll `browser_tab_snapshot` about every 400–500ms for the visible active tab, and after actions. Cancel polling when hidden/unmounted. Native properties provide real URL, title, history capabilities, and loading, including in-page history. `loading: false` does not prove successful navigation: the underlying runtime does not expose every navigation failure. Provide a reload/external-open fallback for failed pages.

## Lifecycle and layout

- Creation starts hidden. Await it before layout/navigation. Coalesce duplicate creation requests in the bridge; an existing or in-progress ID rejects rather than replacing a live view. Maximum eight native views, including pending creations.
- Tab switching should hide/show existing views, not recreate them: this preserves history, scroll, forms, and the page session while the app remains open. Close is idempotent and destroys that tab's native state. Closing during creation cancels that generation safely.
- A full main-document reload/navigation closes all owned native tabs and invalidates pending creations even when React cleanup does not run. Child-page navigation and SPA route changes do not trigger this cleanup. Rehydrated metadata must create fresh native views; page sessions from the previous main document are not retained.
- Layout coordinates are logical window client coordinates, including the app's own titlebar area. At default web zoom, `getBoundingClientRect()` provides these units. With custom web zoom, convert CSS pixels to window logical pixels using `devicePixelRatio / nativeWindowScaleFactor`.
- Visible layout hides other native tabs and clips the rectangle to the window. Zero/no visible area hides; negative or nonfinite coordinates reject after hiding. `visible:false` hides without moving/resizing.
- Native child views appear above DOM content. Call `browser_tabs_hide_all` when a dialog/overlay opens, the dock is hidden, the chat changes, the user signs out, or the owning component unmounts. Close obsolete tabs when removing their metadata; hide alone retains them and counts toward the limit.
- Route tab operations through a per-tab queue and discard stale snapshot promises after selection changes/close. Keep metadata keyed by signed-in user/chat. Do not navigate an old native tab merely because another chat's preview URL changed.

## Isolation and deliberate limits

Only HTTP/HTTPS and exact `about:blank` URLs are accepted; embedded credentials and privileged/local-file schemes are rejected, including navigation initiated by page content. Blank pages are useful initial tabs. Native browser content gets no file, terminal, auth, or Tauri IPC capability, even when navigating to the RIFT app's origin.

Each view uses an ephemeral website data store and disables autofill. It does not share the main RIFT webview's cookies/localStorage or a personal browser profile. Cookies/page state do not survive closing the native view or quitting the app; persisted tab metadata can restore URLs, not a logged-in browser session.

Downloads are denied in this initial implementation. `target="_blank"`/`window.open` navigates the same browser tab after URL validation; it never creates an untracked native window. The existing agent `browse_url` and `open_browser_page` tools are unchanged and do not automatically control/read these tabs or inherit their sessions.
