# Hack Workbench header grid regression

The old mobile `.fui.sidebar-closed` rule had greater specificity than the final
`.fui` refinement. At 320, 390 and 768 pixels it allocated a 52px header and a
112px overview row even when the overview was absent. The current header has
two 52px rows. Thus the empty console started at y=164 with the sidebar closed,
but y=104 with it open.

The final grid now sizes header and overview tracks intrinsically in both sidebar
states. The console retains the flexible `minmax(0,1fr)` track.

Verification: a headless WebKit layout fixture using all five production inline
CSS layers, the header's two 52px rows, and an optional overview checked 20 cases:
320/390/768/800/1280px × open/closed × overview absent/present. Every case kept
the header at 104px, placed the console immediately after the header/overview,
and had no document horizontal overflow. The 14 HackerMode lifecycle tests passed.

This is a CSS layout regression check, not a complete native/mobile interaction
or streaming-performance test. Live CUA browser inspection was unavailable in
this session (`User unavailable`). It does not establish that unrelated tool
failures or all scroll stalls are fixed.
