## Post 3 — Educational

**Objective:** establish clear evaluation criteria and correct a likely misconception.

**Hook:** An approval prompt is not a sandbox.

**X copy:**

> An approval prompt is not a sandbox.
>
> Ask three questions before an agent acts:
> Where will it run?
> Which approval mode is selected?
> What output can I inspect?
>
> Bring those questions to RIFT: {ACCESS_URL}

**LinkedIn copy:**

> An approval prompt is not a sandbox.
>
> One is a decision step. The other is an execution boundary. You need to understand both.
>
> Before evaluating a security agent, ask:
>
> • Where will the command execute?
> • What permissions does that environment have?
> • Which actions pause for review in the selected mode?
> • What output remains available to inspect?
>
> In RIFT’s documented local terminal, shell commands run with the local account’s permissions. Review prompts do not turn that shell into an OS sandbox. Cloud sandbox execution is a separate environment.
>
> We want that distinction to be clear in an evaluation. Bring your workflow and environment requirements: {ACCESS_URL}

**Visual:** two editorial columns, **Approval: a decision** and **Environment: an execution boundary**. **Structure:** slide 1 distinction; slide 2 four questions; slide 3 RIFT evaluation invitation. X uses slide 1 plus the questions in text. **CTA:** Request Access with environment requirements. **Positioning fit:** demonstrates technical precision where less disciplined campaigns might promise universal safety.

## Sequence and quality checks

Publish in the order above across a launch window the team can support; leave room to respond to real questions. Do not promise a seven-day cadence unless staffed. Posts 3 and 6 intentionally revisit control at different levels: education first, product qualification later. Rotate diagrams, direct product, presenter, and type-led visuals to avoid seven near-identical hero crops.

Before each post: approve the copy, replace the access URL, attach the real produced asset, preserve provenance labels, verify the crop, confirm the access process is active, and check that the current release still supports any named behavior. Record questions and workflow requests as research inputs. Do not invent comments, likes, engagement, or testimonials as social proof.
