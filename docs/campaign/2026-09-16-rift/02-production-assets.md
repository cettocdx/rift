# RIFT — Production assets

Part of [Power, under direction](01-agency-handoff.md). All creative and public copy are provisional until approved. These are finished scripts, prompts, and production specifications; no media generation or publishing has been performed.

## Shared production contract

Use the canonical RIFT logo, neutral graphite palette, system sans, and monospace command treatment from the Brand Lock. Use real product captures for functional evidence. A designed or staged workflow carries **Conceptual workflow** or **Staged demonstration** visibly throughout the relevant sequence. A real recording is labeled **Authorized lab demonstration** only after its provenance is verified.

All proposed approval scenes depend on the exact release and mode supporting the depicted decision. If the security surface has no matching approval UI, show the actual available configuration and revise the narration to match; do not borrow the coding console’s approval UI and imply security feature parity. Local execution must be identified as local. A sandbox label is used only for a verified sandbox environment.

Generate background plates without logos, text, UI, or important screen content. Composite the approved UI capture and exact typography afterward. Do not synthesize a customer, founder identity, real company context, successful scan, finding, or performance result.

Working exports: static social 1080×1350 and 1080×1080; vertical video 1080×1920; landscape video 1920×1080; website hero 2400×1350 with a separately composed mobile crop. These are production choices, not claims about current platform limits. Preview every upload in its destination before publication. Keep essential vertical-video copy inside a central safe area with generous top/bottom clearance; adapt to the actual platform overlays.

Record normal-speed product activity. Cut idle time only with an explicit edit transition; never imply a cut sequence is a timing benchmark. Deliver clean master, captioned master, subtitle file, thumbnail, source capture, and edit project. Use real room tone and intelligible voice; music is optional and subordinate. No alarm soundtrack or fake terminal sound effects.

## Three creator-led concepts

### C1 — Before I let it act

**Hook:** “Before I give a security agent a task, I want to know where it will run.”

**Persona:** an actual security engineer or technically fluent founder; first-person language is approved by the speaker. A synthetic alternative is a clearly labeled technical presenter, not an impersonated founder.

**Setting:** ordinary quiet desk, neutral clothing, practical light, one screen. Comfortable expertise, not a costumed operator.

**Exact spoken script, approximately 30 seconds:**

> Before I give a security agent a task, I want to know where it will run. Here’s the workflow I want to evaluate with RIFT: define an authorized objective, check the environment, and understand the approval mode before execution. Then inspect the tool output. This is a conceptual walkthrough; the exact controls depend on the release and mode. RIFT is a terminal-native agentic security workspace. Request access with a workflow you want to evaluate.

**Shot list and text:**

| Time   | Shot                                                      | On-screen text                   |
| ------ | --------------------------------------------------------- | -------------------------------- |
| 0–5s   | Direct-to-camera opening, static medium close-up          | Where will it run?               |
| 5–11s  | Hard cut to a single objective in the concept layout      | 01 / Objective                   |
| 11–17s | Readable environment and permissions detail               | 02 / Environment + approval mode |
| 17–23s | One tool-output detail; do not invent successful findings | 03 / Inspect the output          |
| 23–30s | Back to speaker; plain end card                           | RIFT / Request Access            |

Keep **Conceptual workflow** visible on the UI sequences and in the caption. B-roll is hands resting near the keyboard, not random typing. Product interaction is a narrated review of objective and execution context; a simulated click never masquerades as a live run.

**CTA:** “Request access with a workflow you want to evaluate.” Destination: approved request page.

**Image prompt:** “Vertical 9:16 editorial photograph of a fictional adult technical presenter at a quiet practical desk, neutral dark shirt, relaxed expression, natural side-window lighting, matte graphite surroundings, ordinary keyboard, screen angled away with no visible content, 50mm-equivalent perspective, realistic skin texture, room for captions, no branding, no text, no hacker styling, no neon, no resemblance requested to any real person. Reference plate for a clearly disclosed synthetic presenter.”

**Video prompt:** “Create a five-second 9:16 reference B-roll shot of the same fictional presenter seated at the same desk, listening and then glancing toward an off-frame monitor. Camera locked, natural small movements, plausible hands resting still, soft side light, no dialogue, no lip-sync, no screen text, no logos, no dramatic effects. Maintain wardrobe and face consistency with the approved reference. This is atmospheric footage, not a customer testimonial.”

**Edit instruction:** preferably film a real consenting speaker for the spoken body. If synthetic, disclose **AI-generated presenter · conceptual workflow**, record/synthesize only the approved script, and review every spoken word. Generate short B-roll plates, then edit with exact UI and captions rather than asking one generation to invent the whole demonstration.

### C2 — The work between the commands

**Hook:** “The command is rarely the whole job.”

**Persona:** a working operator explaining a common workflow pattern; no claim that they are a RIFT customer.

**Setting:** screen-led walkthrough with a small face-camera opening and closing. Three simple written labels: objective, output, next step.

**Exact spoken script, approximately 30 seconds:**

> The command is rarely the whole job. There’s the objective, the output, and the decision about what comes next. Those handoffs are what I’d evaluate in an agentic security workspace. With RIFT, the point is tool-based execution you can inspect, not just an answer to read. This is a simulated workflow, so treat it as an explanation, not a performance result. Bring a real, authorized workflow. Request access to evaluate RIFT against it.

**Shot list and text:**

| Time   | Shot                                                                        | On-screen text                    |
| ------ | --------------------------------------------------------------------------- | --------------------------------- |
| 0–4s   | Speaker at desk, immediate opening                                          | The work between commands         |
| 4–10s  | Three editorial cards, not fake application windows                         | Objective → Output → Next step    |
| 10–18s | Conceptual terminal layout showing one task and a placeholder output region | Simulated workflow                |
| 18–24s | Detail view explaining the relationship between result and next action      | What informs the next step?       |
| 24–30s | Speaker, then clean brand card                                              | Bring a workflow / Request Access |

**B-roll:** a note beside a keyboard and a genuine screen capture if approved. Avoid exaggerated chaos or dozens of browser tabs. **Product interaction:** expand available output detail in a release-verified capture; otherwise use editorial cards, not invented product controls.

**CTA:** “Bring a real, authorized workflow. Request access.”

**Image prompt:** “Portrait 9:16 editorial desk scene, graphite tabletop, a plain notebook containing no writing, one unbranded keyboard, neutral monitor with a blank matte screen, side daylight, practical lived-in neatness, restrained grayscale, 50mm lens feel, no text, no logos, no glowing code, no clutter. Leave the middle upper region available for an exact screen composite.”

**Video prompt:** “Six-second static overhead-to-oblique desk B-roll from the approved still reference, one adult hand moves a blank note beside an unbranded keyboard, then rests. Realistic anatomy, no typing, no visible generated words, no screen content, neutral daylight, quiet technical workplace. Keep the camera stable and the screen geometry planar for compositing.”

**Edit instruction:** build the three labels as exact editorial text. Use a clearly labeled simulated sequence until a real release capture exists. Do not put a stopwatch or productivity multiplier on the scene.

### C3 — Open the output

**Hook:** “A confident summary isn’t enough. Show me the output.”

**Persona:** security researcher or founder speaking about an evaluation criterion. Their personal experience is not fabricated.

**Setting:** quiet screen-share, voice-led, one tool result occupying the frame; face camera optional.

**Exact spoken script, approximately 30 seconds:**

> A confident summary isn’t enough. Show me the output. When I evaluate a security agent, I want to understand what ran, where it ran, and what the result actually supports. That’s the lens for this RIFT walkthrough. We’re showing a conceptual review sequence, not a completed assessment or an audit certification. The goal is simple: agentic execution an operator can interrogate. Request access and bring a workflow worth testing.

**Shot list and text:**

| Time   | Shot                                                                                | On-screen text                |
| ------ | ----------------------------------------------------------------------------------- | ----------------------------- |
| 0–5s   | Speaker or title over neutral frame                                                 | Show me the output.           |
| 5–12s  | Editorial callouts around one conceptual result block                               | What ran? / Where?            |
| 12–20s | Close crop of actual verified output if available; otherwise abstract labeled block | What does the result support? |
| 20–25s | Return to the original objective; no fabricated success badge                       | Conceptual review sequence    |
| 25–30s | Brand and CTA                                                                       | RIFT / Request Access         |

**B-roll:** one actual output inspection and one neutral speaker close-up. **Product interaction:** reveal the exact output detail supported in the selected release. Preserve failures and uncertainty. Do not simulate log export, retention settings, or signed receipts.

**CTA:** “Request access and bring a workflow worth testing.”

**Image prompt:** “Landscape 16:9 graphite workstation background plate, nearly straight-on unbranded flat display with blank screen, subtle side lighting, dark neutral wall, one small practical lamp outside the main focus, crisp rectangular screen geometry, no text, no icons, no generated data, generous screen area for a separately composited readable product crop, no sci-fi clutter.”

**Video prompt:** “Five-second very slow camera push of no more than three percent toward the blank planar display in the approved reference, neutral illumination, no screen animation, no people, no words, no logos, no shifting geometry. Create only the atmospheric plate; exact RIFT UI will be inserted in post-production.”

**Edit instruction:** use straight-on native-resolution product capture for the educational portion; the generated plate belongs only in the opening or closing. Never make text harder to read to preserve an atmospheric angle.

## Three product visualization directions

### P1 — The working surface / clean product hero

**Purpose:** establish the actual product before asking the audience to accept a category story.

**Final background-generation prompt:** “Create a 16:9 software-launch background plate at 2400×1350 composition. Matte graphite canvas #101214, a single restrained raised plane on the right occupying 58 percent of the frame, broad soft overhead light, subtle depth at its edges, nearly straight-on perspective, generous clean negative space on the left for a headline. Neutral grayscale with a very faint restrained blue edge cue #2F7AE5. No screen content, text, logo, keyboard, person, padlock, map, HUD, particles, hologram, extra panels, or green light. Precision comes from geometry and space, not spectacle. Keep the right plane suitable for an exact flat product-screen composite.”

**Composition:** copy on left, one verified RIFT view on right. **Lighting:** broad soft studio source; no luminous fog. **Camera:** near-orthographic. **Interface framing:** one operation detail, not a tiny full application with unreadable text. **Surface details:** matte, faint edge separation, no chrome ornament.

**Composite recipe:** insert a real release capture; retain its actual environment and mode labels. Add canonical logo separately. Headline: **Security execution. Under your direction.** Add a provenance label if staged. Desktop UI may extend below the hero, but the meaningful state cannot be cropped away.

**Protected elements:** logo proportions, UI strings, actual action state, terminal content, environment meaning. **Negative constraints:** invented data, pixel-distorted output, replacement logo, fake certification stamp, universal “sandboxed” badge.

**Variants:** mobile uses copy above a front-on output crop; social uses the same moment with a shorter headline. Alt-text draft: “RIFT workspace showing a tool-action detail and its execution context.” Revise it to describe the final actual capture.

### P2 — At the operator’s desk / contextual use

**Purpose:** show RIFT as a practical working instrument without inventing a customer story.

**Final background-generation prompt:** “Editorial product-use photograph, 4:5 composition, fictional adult operator seated at an ordinary tidy desk, face mostly outside frame, natural posture, neutral cotton shirt, realistic hands resting beside an unbranded keyboard, single unbranded monitor at a modest angle with blank planar screen for compositing, graphite and warm-neutral office materials, soft window light, 50mm-equivalent lens, screen occupies at least half the useful composition, technically credible everyday workplace, no logos, no text, no hood, no server room, no neon, no weapon, no stock-photo handshake, no exaggerated facial performance.”

**Composition:** screen dominates; person supplies scale and context. **Lighting:** daylight plus a low practical fill. **Camera:** over-shoulder with shallow angle; no extreme lens distortion. **Interface framing:** actual product crop inserted with a tracked planar transform; offer a separate front-on close-up for reading. **Surface details:** ordinary desk, restrained wear, no luxury gadget collection.

**Composite recipe:** use an approved captured workflow. Caption: **An operator’s view of agentic security work.** If generated, caption metadata says **Illustrative scene**; if UI staged, show that label on the UI too. No invented person name, job title, employer, or quotation.

**Protected elements:** canonical screen proportions, truthful interaction state, no identity implication. **Negative constraints:** generated fingers on keys performing impossible actions, illegible code, customer-logo stickers, made-up team surroundings.

**Variants:** landscape crop adds copy beside the desk; vertical keeps the screen near center and crops the desk before shrinking the output.

### P3 — Within the frame / cinematic campaign concept

**Purpose:** translate control into composition rather than a claim of perfect containment.

**Final background-generation prompt:** “Restrained cinematic abstract software-campaign plate, 16:9. A single matte graphite rectangular plane floats only slightly above a dark graphite floor. One precise thin boundary line frames the plane, a narrow blue highlight marks one edge, soft overhead light reveals material depth, distant background falls to neutral darkness. Architecture is sparse and physically plausible. The central plane remains flat and blank for compositing a software workspace. No cage, fortress, shield, lock, weapon, globe, tunnel, portal, neon city, laser grid, tiny text, logos, symbols, smoke clouds, energy effects, or additional screens. Communicate disciplined attention through stillness and proportion.”

**Composition:** one framed workspace, balanced negative space, one light boundary. **Lighting:** controlled overhead strip with soft falloff. **Camera:** 50mm-like shallow elevation, minimal perspective. **Interface framing:** central product crop remains legible; no surrounding fictional telemetry. **Surface details:** graphite, fine grain, softened reflection only below the surface.

**Composite recipe:** headline **Power, under direction.** Subline **A terminal-native agentic security workspace.** Place exact UI and logo in post. Caption it **Campaign visualization**. The boundary is an art-direction device, not a literal representation of sandbox enforcement.

**Protected elements:** product identity and truthful capture; the artwork must not imply physical isolation guarantees. **Negative constraints:** militarization, impenetrable barrier metaphor, explosion, fake 3D brand mark.

**Motion:** optional six-second loop with subtle camera drift under 3%, static UI, and a still-frame fallback. No animated boundary scanning. Label the image as illustrative wherever viewers could mistake it for product proof.

1. **Security execution. Under your direction.** — autonomy and operator control.
2. **Before the command, know the context.** — environment and approval awareness.
3. **The work doesn’t end at the prompt.** — tool execution and follow-through.
4. **A result worth reading starts with output you can inspect.** — evidence quality.
5. **Bring a workflow. See where RIFT fits.** — concrete evaluation and qualification.

These hooks belong to one message system; they are not simultaneous hero headlines.

### Test and delivery discipline

Compare S1 with a message-only variant before changing visual, audience, and CTA together. Compare P1 versus P3 with identical copy to isolate the effect of atmosphere. Use the qualification rubric and funnel definitions in the handoff. Video completion and click-through are secondary signals; requests that progress into an evaluation are the commercial outcome.

Use asset IDs in filenames, for example `rift-directed-S1-4x5-v01.png` and `rift-directed-C1-9x16-captioned-v01.mp4`. Save a provenance note with each asset: capture source, release/mode, whether staged, presenter permissions, generated components, and review owner. Do not publish a file named “final” until both creative and product reviews have approved the actual export.
