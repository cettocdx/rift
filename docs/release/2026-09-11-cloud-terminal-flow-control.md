# Cloud terminal output flow control

The installed E2B 2.27.0 SDK accepts asynchronous PTY callbacks but does not await them. Returning a promise from RIFT alone would therefore create another unbounded backlog. A regression against the installed SDK's actual event loop demonstrated 64 events read while the first consumer callback was withheld, instead of one.

A narrow pnpm patch now awaits the PTY callback in both the CommonJS and ESM distributions. This follows the upstream fix in [E2B CommandHandle](https://github.com/e2b-dev/E2B/blob/main/packages/js-sdk/src/sandbox/commands/commandHandle.ts); the upstream issue is [#1259](https://github.com/e2b-dev/E2B/issues/1259). The rest of this pinned SDK version remains unchanged. The patch is tracked in the workspace manifest and lockfile and must remain applied until a tested SDK upgrade includes the fix.

The RIFT E2B adapter exposes per-reader output credit to the demand-driven SSE stream introduced for local terminals. It awaits credit before dispatch, splits large SDK deliveries into at most 64 KiB slices, and waits after delivery before the SDK reads again. Multiple readers use the slowest-reader policy. Input, resize and kill use separate RPCs; a successful kill or already-gone result releases the waiting callback. A failed kill RPC does not silently disable subsequent output. Reader cancellation releases its own credit without killing the underlying terminal.

A real isolated E2B sandbox ran a Python Unicode burst through the actual adapter, session manager and stream. No model was called. The sandbox was killed after the probe. With reads withheld for 300 ms, RIFT received zero additional output bytes. It subsequently drained all 4,718,598 expected bytes (4.5 MiB plus a readiness marker), with an exact byte match, no reset, and exit code zero. The largest observed raw frame was 10,241 bytes and the replay ring peaked at 262,144 bytes. Startup shell output explains why the final absolute cursor (4,718,732) exceeds the compared payload size. Payload SHA-256: `435ef704fa5b5e406717376100a7139acb7547c2d31a4635095374176a8f9789`.

This bounds RIFT's SDK-to-SSE read-ahead and its raw replay retention. It does not establish a bound on every E2B service, HTTP/2, OS, browser or total-process buffer. Output produced while all observers are detached still follows existing bounded replay/truncation rules; unlimited disconnected history and survival of a web process loss are separate contracts. Native desktop v2 terminal behavior is unchanged.

Focused adapter/SDK/stream integration checks passed 37 tests across four suites. The SDK regression was observed failing before the dependency patch; two adapter-credit regressions failed before capability wiring and passed afterward.
