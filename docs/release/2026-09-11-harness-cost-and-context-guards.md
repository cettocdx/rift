# Harness funding, summarization and unnecessary work

The web chat driver constructed a BudgetMonitor only when a monthly allowance snapshot existed. Balance-funded Ask/Plan requests could therefore miss the existing worker's mid-run funding guard. Conversely, a paid balance-funded request could retain an exhausted monthly snapshot before the fallback expression checked its funding source. This could stop a funded request for the wrong reason.

The web driver now uses a funding-aware constructor built from the existing run-cost policy; monthly snapshot capture excludes balance-funded requests in both drivers. No fixed $5 or other arbitrary default cap was added. Existing account funding, retail-to-provider conversion, operator limits, free allowance and grace policy remain. Behavioral tests cover free and paid prepaid runs, exhausted allowance snapshots, operator ceilings and uncapped-by-default monthly runs. This is an after-model-step check, not a new pre-authorization or reservation for every concurrent paid tool.

Summarization retains tool schemas for prefix compatibility but sends toolChoice none, with inert executors as a second safeguard. A blank or whitespace-only response cannot replace the original history or be saved as a valid summary, even when a transcript notice exists. The first request using a new Anthropic summary now gets the same explicit cache marker as ordinary steps; a real AI SDK loop test checks the first and following summarized requests. No cache-hit or dollar-saving percentage is inferred from these offline tests.

Fresh, text-only greetings already disable external tools through a conservative classifier. The worker nevertheless started an E2B sandbox proactively. It now skips that optional allocation only for those classified cloud greetings. Actual work still warms the sandbox concurrently with model setup; selected local-computer access remains mandatory, and cancellation prevents new preparation. The selected model still generates the answer. Five preparation tests plus greeting and worker-contract suites passed 75 tests; the new no-allocation case failed before the guard.
