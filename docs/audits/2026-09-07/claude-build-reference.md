# RIFT Build → Claude Code çalışma davranışı referansı

**İnceleme: 7 Eylül 2026.** Yalnız Anthropic’in güncel resmî belgeleri ve mevcut Rift kaynakları kullanıldı. Belgelerin çoğu yayın tarihi vermiyor; aşağıdaki davranışlar erişim anının sözleşmesidir. SDK/binary sürümü sabitlenip doğrulanmadan sürüme bağlı varsayılanlara güvenilmemeli. Bu not araştırmadır; motor seçimi veya tamamlanmış geçiş iddiası değildir.

**Karar sınırı:** Anthropic, Agent SDK’nın Claude Code’un araçlarını, ajan döngüsünü ve context yönetimini uygulamaya gömdüğünü belgeliyor. Çok modelli özel Rift döngüsü bu davranışları uygulayabilir; aynı iç harness veya aynı sonuç kalitesini iddia edemez. Agent SDK, Client SDK ve Anthropic tarafından barındırılan Managed Agents ayrı ürünlerdir. [Agent SDK overview — Anthropic](https://code.claude.com/docs/en/agent-sdk/overview)

## Belgelenmiş davranış → Build gereksinimi

| Alan | Belgelenmiş davranış | Rift’e uygulanacak sözleşme |
| --- | --- | --- |
| Döngü ve çıktı | Prompt → model kararı → bir veya çok araç çağrısı → araç sonuçları → tekrar. Araç çağrısız yanıt normal bitiştir. Son `AssistantMessage` ardından aynı final metni içerebilen `ResultMessage` gelir; result subtype başarı/limit/hata ayrımını taşır. `maxTurns` araç kullanım turlarını, `maxBudgetUsd` harcamayı sınırlar. [Agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop) | Tek görünür assistant yanıtı; araç sonuçlarından sonra devam; sonuç mesajından ikinci cevap üretmeme; limit ve iptali başarıya çevirmeme. |
| Araçlar ve paralellik | `Read/Edit/Write`, `Glob/Grep`, `Bash`, `WebSearch/WebFetch`, `ToolSearch`, `Agent/Skill/AskUserQuestion` ve görev araçları bulunur. Salt okunur araçlar paralel, durum değiştiren araçlar sıralı çalışabilir; özel araçlar varsayılan olarak sıralıdır. MCP ile genişler. [Agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop) | Dosya/arama/terminal araçlarının gerçek sonuçlarını döngüye ver; bağımsız okumaları paralelleştir; çakışan yazıları sırala. Mevcut Rift MCP ve doğrulama araçlarını adapter üzerinden taşı. |
| Context | Context doldukça önce eski araç çıktıları temizlenir, gerekirse geçmiş özetlenir. Eski ayrıntılar kaybolabilir; kalıcı kurallar `CLAUDE.md` içindir. Skills gerektiğinde yüklenir, MCP şemaları desteklenen yapılandırmalarda araç aramasıyla ertelenir. [How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works) SDK compaction sırasında `compact_boundary` bildirir. [Agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop) | Özet hedefi, kısıtları, dosyaları, kararları, doğrulama sonucunu ve açık işleri korusun. Özet eski geçmişin yerine kalıcı geçsin; tekrar dolma durumu ölçülsün. Büyük çıktılar kanıt deposunda, kısa özeti context’te tutulsun. |
| İzin değerlendirmesi | Sıra: hooks → deny → ask → mode → allow → `canUseTool`. `allowedTools` yalnız otomatik onaydır; listede olmayan araçları kaldırmaz. Daha erken onaylanan çağrı callback’i atlayabilir. Her çağrıyı denetleyen kontrol `PreToolUse` içindir. `plan` yazmaları callback’e gönderir; uygulama bunları reddetmezse salt okunur sınırı yalnız isme bırakılamaz. [Permissions](https://code.claude.com/docs/en/agent-sdk/permissions) | Rift’in Ask/Approve for me/Full access arayüzü korunsun; isim eşlemek yerine mevcut politika açıkça uygulansın. Ask ve unknown MCP için gerçek bekleme/ret; iptal bekleyen aracı çalıştırmamalı. |
| İzolasyon | Bash sandbox’ı komutun erişebileceği dosya/ağı sınırlar; approval mode komutun çalışıp çalışmayacağını belirler. Bunlar bağımsızdır. `failIfUnavailable` ve `allowUnsandboxedCommands` fallback davranışını kontrol eder. [Sandboxing](https://code.claude.com/docs/en/sandboxing) | SDK kullanmak Rift’in kullanıcı/proje izolasyonunu kendiliğinden sağlamaz. Mevcut sandbox, grant ve kullanıcı yetkileri korunmalı. |
| Alt ajanlar | Normal alt ajan parent geçmişini değil kendi prompt’unu, görev metnini, proje context’ini ve izinli araçlarını alır; parent’a final sonuç döner. Fork context devralabilir. Güncel belgelerde background varsayılanı ve nested agents vardır; derinlik, eşzamanlılık ve toplam harcama sınırları ayarlanabilir ve sürüme bağlıdır. [Subagents](https://code.claude.com/docs/en/agent-sdk/subagents) | Bounded araştırmacı ile gerçekten araç çalıştırabilen alt ajanı ayır. Görev, bağlam ve dosya sahipliği açık; child iptali ve toplam bütçe parent’a bağlı olmalı. |
| Oturum devamı | `resume` belirli session ID’yi açar; `continue` dizindeki en son oturumu seçer. Oturumlar JSONL olarak saklanır. Başka hostta devam için dosyaları/SessionStore’u taşımak gerekir. `forkSession` konuşmayı dallandırır, dosya sistemini ayırmaz. [Sessions](https://code.claude.com/docs/en/agent-sdk/sessions) | Çok kullanıcılı Rift’te explicit `(user, chat, project, engine, sessionId)` bağı kullan; “en son oturum” seçme. Browser reconnect ile motor session resume iki ayrı süreç olsun. |
| Checkpoint/Undo | `enableFileCheckpointing` ve user-message checkpoint UUID’leriyle `rewindFiles` kullanılabilir. `Write/Edit/NotebookEdit` değişiklikleri kapsanır; Bash değişiklikleri ve çoğu subagent edit’i kapsanmaz. Foreground `context: fork` skill istisnadır. Dosya rewind konuşmayı geri almaz; aynı session’a bağlıdır. [File checkpointing](https://code.claude.com/docs/en/agent-sdk/file-checkpointing) | “Undo all” vaadi verme. Tüm araç yollarının geri alınması isteniyorsa Rift ayrıca workspace/git snapshot ve değişen dosya kaydı tutmalı; harici API yan etkileri dosya undo’su değildir. |
| Doğrulama | Claude varsayılan olarak işin bittiğine karar verir; doğrulama güvencesi otomatik değildir. Resmî öneri test/build/lint/fixture/screenshot gibi okunabilir başarı ölçütüdür. Stop hook kontrolü bitişi engelleyebilir; belgelenen ardışık engelleme sınırı 8’dir. [Best practices](https://code.claude.com/docs/en/best-practices) | Mevcut `verify_app`/kanıt kapısı korunsun. UI değişikliği için çalışan uygulama görüntüsü, kod için anlamlı test sonucu; evidence olmadan “verified” etiketi verilmesin. |
| Hook hata/iptal davranışı | Güncel SDK’da `PreToolUse` timeout aracı çalıştırmaz; Stop/SubagentStop timeout ise uyarıdan sonra normal durabilir. Hook beklerken interrupt pending tool’u iptal eder; bu davranışların sürüm eşikleri vardır. [Hooks](https://code.claude.com/docs/en/agent-sdk/hooks) | Kritik approval/verification kararını yalnız hook’un varlığına bağlama. İptal, timeout ve belirsiz sonuç Rift run kaydında ayrı tutulmalı; driver ve worker cleanup ayrıca çalışmalı. |

## SDK mı, özel çok modelli harness mi?

| Seçenek | Sağladığı | Rift’in üstleneceği |
| --- | --- | --- |
| Gerçek Claude Agent SDK | Belgelenmiş Claude Code döngüsü, yerleşik araçlar, context ve session altyapısı. | Stream adapter, tenant/sandbox izolasyonu, kalıcı session depolama, mevcut approval UI, run claims, maliyet kaydı ve doğrulama entegrasyonu. SDK yerel process içinde çalışır; barındırma Rift’e aittir. [Overview](https://code.claude.com/docs/en/agent-sdk/overview) |
| Rift’in kendi çok modelli döngüsü | Mevcut model/provider seçimi, sandbox ve araçların tek yürütücüyle korunması. | Döngü, compaction, session, gerçek alt ajanlar, checkpoint ve bütün davranış testleri Rift’in sorumluluğu. Bu bir mimari çıkarımdır; Claude Code’un özel implementasyonunun kopyası değildir. |

SDK quickstart’ı Anthropic API ve Claude sağlayan Bedrock, Claude Platform on AWS, Google Cloud Agent Platform/Vertex ve Microsoft Foundry yollarını belgeliyor. Bu, mevcut GPT/Gemini/diğer modellerin Agent SDK altında aynı şekilde çalışacağına kanıt değildir. Üçüncü taraf üründe claude.ai login/rate-limit kullanımına ön onay olmadan izin verilmediği belirtiliyor; ürün entegrasyonu için belgelenmiş API kimlik doğrulaması kullanılmalı. [Quickstart](https://code.claude.com/docs/en/agent-sdk/quickstart)

SDK’nın configuration yüklemesi de açıkça seçilmeli. Güncel doküman çok kiracılı kullanımda varsayılan `query()` ayarlarına güvenilmemesini, kullanıcı başına dosya sistemi izolasyonu, `settingSources: []` ve `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` öneriyor; bazı host/managed ayarları `settingSources` dışında kalabiliyor. Rift kuralları ayrıca kontrollü aktarılmalı. [Configuration loading](https://code.claude.com/docs/en/agent-sdk/claude-code-features)

## Geçiş kabul ölçütleri — öneri

1. Aynı prompt için bir assistant cevabı; tool-result sonrası devam; text/result tekrarının gösterilmemesi.
2. Ask/Auto/Full, desktop/cloud ve MCP yollarında aynı Rift politikası; pending approval sırasında Stop → sıfır yeni tool çalışması.
3. Queue, startup, stream ve reconnect yarışlarında tek yetkili run; eski cleanup yeni çalışmanın chat/todo durumunu değiştiremez.
4. Uzun fixture’da context dolunca hedef/kararlar korunur, eski büyük transcript yeniden eklenmez; limit başarısızlığı görünür kalır.
5. Session resume doğru kullanıcı/projeye bağlanır; fork dosya izolasyonu varsa ayrıca doğrulanır. Undo kapsamı gerçek dosya kanıtıyla sınanır.
6. Araçlı alt ajan varsa iptal, izin, toplam maliyet ve dosya sahipliği parent’la tutarlı; araçsız analiz “dosyaları test etti” diye sunulmaz.
7. Build tamamlandı iddiası test/çalışan UI kanıtına bağlıdır. Sabit görev/model/bütçe fixture’ları olmadan Claude Code ile eşit güç veya başarı oranı iddia edilmez.

**Kamuya açık olmayan/kanıtlanmayan kısım:** Bu kaynaklar tüm özel optimizasyonları, model ağırlıklarını veya her internal prompt/heuristic’in birebir uygulanabilir tanımını sunmuyor. SDK’nın belgelenmiş aynı-loop sözleşmesi, aynı model/araç/çalışma ortamı dışında aynı sonuç garantisi değildir. Agent SDK entegrasyonunda ürünün Rift kimliği korunmalı; Anthropic rehberi ürünün “Claude Code” olarak markalanmasını da yasaklıyor.
