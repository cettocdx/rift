## Requirements already present; preserve them

- Settings is an item in the account dropdown (`SidebarUserNav.tsx:380-386`), while Monthly usage precedes the account trigger (`:437-440`). Do not add a permanent Settings row.
- The settings exit reads **Back to app** (`SettingsShell.tsx:75-82`).
- The compact rail already has 500 weight and semantic idle/selected colors (`workspace.css:582-595,1184-1212`). Avoid another global increase that makes idle labels as loud as selected ones.
- The current conversation row sources do not render the removed `3d/4d` timestamps. Remaining timestamp CSS is not evidence that timestamps are visible. Shortcut hiding remains in the workspace rule (`workspace.css:1219-1220`).
- Plugins already uses a persistent tablist with roving keyboard focus and a neutral focus-visible ring. Preserve that fix while keeping panel state.

## Validation boundary and bounded follow-up

These six findings are source-backed. No new live visual pass or runtime font measurement was performed in this audit. The parent implementation owns shared CSS/Settings/Studio changes. The bounded follow-up assigned here is More collapse plus Plugins/Skills state preservation, with behavior tests; its results will be recorded below when complete.

## Implemented follow-up and verification

- More now reveals a newly entered secondary route, then respects an explicit collapse on that route. Click, Enter and Space work in both sidebar variants. A small quiet indicator remains when the current destination is inside the collapsed group.
- Plugins/Skills mount a panel on its first visit and retain its DOM, query, category and scroll state until leaving the workbench. Inactive panels are hidden, inert and excluded from accessible navigation. Their portalled connection menus, endpoint/detail dialogs, create-skill dialog and armed removal confirmation close on deactivation. Query subscriptions stay alive for visited panels; this is in-memory continuity, not persistence across app restart.
- PluginsWorkbench and SkillsPanel no longer pin dark backgrounds or dividers to literal grays. Skills functional text and the extension tabs now use the existing body/nav/label/caption/section roles. No global CSS or Settings/Studio implementation was changed in this follow-up.
- **67 tests passed across 5 suites:** SidebarPremiumNavigation, PluginsWorkbench, McpMarketplace.ux, SkillsPanel.marketplace and PluginRouteStates. The new behavior checks fail against the old collapse/unmount behavior and pass after the changes. Actual panel tests also verify transient portal cleanup without network connections or mutations. Scoped ESLint and diff whitespace checks passed.
- Local logs: `/tmp/rift-native-nav-tests.log`, `/tmp/rift-native-nav-lint.log`, `/tmp/rift-native-nav-format.log`. This pass did not perform native/browser visual QA or a new whole-project TypeScript run. Appearance-scale and theme rendering should be checked in the running preview alongside the parent changes.

## Final source review: shell, settings, native menu and dock keyboard

This bounded review inspected `ThemeProvider`, `ProChatLayout`, `useProKeyboardShortcuts`, `SettingsShell`, `SettingsNav`, `settings-return`, and `WorkbenchDock`, plus their direct native/event contracts. No UI automation or implementation edits were performed by this review. Existing test source was inspected; live native verification remains separately reported.

| **Confirmed P2, corrected during review:** returning from Settings lost query-only navigation. The shell remembered only pathname changes, so switching `/plugins` to `/plugins?tab=skills` did not update the saved return destination. The account Settings entry uses a Link and does not call `openSettings`. | `ProChatLayout.tsx:67-91` now observes the serialized search parameters alongside pathname; the new shell regression exercises the query-only update. | Returning to the app should preserve the selected tab/filter regardless of which Settings entry opened it. |

The return helper rejects external URLs and auth/settings detours, and restricts a `/lab/app` return destination to that scope. It preserves an observed query and hash. Hash-only changes are not subscribed separately; this review does not claim preservation of arbitrary fragment navigation or in-memory page state after unmount.

Native menu focus has an explicit implementation: `packages/desktop/src-tauri/src/lib.rs` focuses the main webview before emitting `rift:desktop-menu-action`; the browser's overlay observer hides native child views while a dialog is open. The event listener handles late subscription completion and ignores queued callbacks after cleanup. The installed Wry 0.55.1 macOS source documents that child webviews hand Command-key equivalents to the native menu instead of JavaScript. Consequently, the presence of both DOM and native listeners alone is not evidence that one physical shortcut dispatches twice. The frontend menu tests cover event delivery/cleanup, not actual AppKit accelerator behavior; that needs the rebuilt native app check.

Theme synchronization waits for the resolved appearance, invokes only from the desktop interface, and tolerates older desktop builds without the command. The native command rejects child-webview callers. No additional material regression was established in the reviewed theme or Settings navigation changes.

The dock reveals the selected tab wrapper (including close control) within its own horizontal strip, uses immediate scrolling for keyboard selection/reduced motion, and retains focus via `preventScroll`. Resize/unmount cleanup is explicit. Existing behavioral coverage checks selection/focus, close-neighbor behavior, isolated scrolling, resize and reopen. No additional material keyboard-navigation defect was established in this source review.
