# Native browser work and completed-response presentation

2026-09-08 · `codex/reference-ui-rebuild` · RIFT UI Preview checkout.

## Changes and evidence

| Before | After | Why |
| --- | --- | --- |
| A visible native browser measured its rectangle on each of 20 unrelated transcript updates/scroll events. | Zero event-driven rectangle reads in that controlled regression. | Sibling conversation output cannot move the browser host. Mutation checks now filter for native ancestors and inserted/removed/changed overlays; sibling scrolling is ignored. |
| Unchanged native snapshots repeatedly published the same title (four callbacks in the regression). | One title notification; equal snapshots preserve state identity. | Avoid idle polling causing redundant React work. The dock already guarded identical title dispatches; this fixes the browser's own redundant updates. |
| A saved final Hack response could remain absent from an already-hydrated local transcript. | On idle, with no server stream, a saved final answer replaces an incomplete local answer with exactly the same message ID. | The UI should show existing evidence instead of declaring that no final response arrived. This is presentation reconciliation, not an execution retry. |

Native layout still reacts to viewport resize, ancestor scrolling, dialog/menu state, native scale and document visibility. The periodic position safety check and execution-time visibility fencing remain. Tests disable the periodic check only to isolate event-driven work; they also insert a dialog inside a wrapper and verify immediate native hide and subsequent restoration. Existing stale-navigation, hidden-tab and serialized-command tests remain green.

The final-answer warning is generated by `HackTurnTranscript` when the local turn is idle, has work-log entries and has no prose after its last tool. It does not encode a provider error or a disconnect cause. Read-only metadata from the inspected saved session showed `finish_reason=stop`, no active stream, no cancellation and no persisted run error; inspected saved assistant turns had trailing prose. This supports checking client/server presentation, but does not identify the exact transient state that produced the user's warning. New tests reproduce that presentation gap with synthetic, harmless file-check messages. Already-complete local answers, live output, newer user messages and mismatched IDs are preserved. Actual tool-only endings can still produce the warning: no final answer is fabricated.

Single 100 ms frame gaps remain despite no observed long tasks; their cause is not established by this aggregate trace.
